# Changelog

Skills and repo tooling. [`skill-land`](tools/skill-land/CHANGELOG.md) versions separately.

## Unreleased

### Fixed
- **CI never ran the `skill-land` tests.** `check.yml` had two jobs, `manifest` and `evidence-loop`.
  The suite ran only when someone remembered to run it by hand, so a green check said nothing about
  the package, and `publish-skill-land.yml` fires on a tag and would ship whatever was there. For a
  tool whose whole claim is that nothing in the ecosystem verifies what it asserts, keeping its own
  suite outside CI was the same failure one level up.
- **`publish-skill-land.yml` granted `contents: read`**, so `gh release create` 403'd *after*
  `npm publish` had already succeeded — a red run that shipped a package. Latent since the file was
  written; never reached, because the publish step had always failed first. Now `contents: write`.

### Notes
- **The publish workflow had never succeeded.** Both of its runs before 2026-09-05 failed, so
  `skill-land` 1.1.0 on npm was released by hand, not by the automation the docs described. The
  cause was that no npm Trusted Publisher was configured for the package: npm falls back to token
  auth when the registry reports no matching publisher, found `setup-node`'s placeholder
  `NODE_AUTH_TOKEN`, and got `404` on `PUT`. Fixed by configuring the publisher on npmjs.com;
  `skill-land` 1.2.0 is the first release this workflow has actually produced, with signed
  provenance.
- **`skill-land` 1.3.0** fixes a bug of the same shape as the one above: it copied and verified
  `SKILL.md` alone, so a 1-of-148-file install of `impeccable` reported "verified". Found by
  running 1.2.0's own `--verify --all` against a real `~/.agents/skills` and checking all three
  failures it reported — every one was false. See
  [tools/skill-land/CHANGELOG.md](tools/skill-land/CHANGELOG.md).
- **Antigravity's global skill directories are now live-verified**, not inferred: a canary skill in
  each candidate directory, then `agy -p "/skills"` from a neutral workspace on `agy` 1.1.27.
  `~/.gemini/config/skills`, `~/.gemini/skills` and `~/.gemini/antigravity-cli/skills` are read;
  `~/.agents/skills` and `~/.gemini/antigravity/skills` are not. Details in
  [tools/skill-land/CHANGELOG.md](tools/skill-land/CHANGELOG.md).

## 0.3.0

### Added
- **`evidence-loop`, the second skill in this repo.** Enforces a deterministic evidence lifecycle
  for repeated experiments — raw artifact verified, result recorded, result reviewed, artifact
  committed to git, closure recorded, closure reviewed — before any hypothesis conclusion is
  allowed. Unlike every other skill here, its `SKILL.md` is not self-contained: it only tells an
  agent how to drive a companion Rust CLI (`tools/evidence-loop/`), which enforces the state machine
  itself so the guarantee doesn't depend on a model following prompt instructions.
- **The `tools/evidence-loop` Rust CLI**, built with `cargo build --release` and put on `PATH`.
  Covered by `cargo test` in CI (`.github/workflows/check.yml`).
- **`docs/evidence-loop/`**: `protocol.md` (why enforcement lives outside the prompt),
  `state-machine.md`, `board-format.md`, and `soak-notes.md` (validation notes, including the S001
  evidence-bundle and S014 local-only-artifact refinements, and the E004 cold independent review).

### Notes
- One invocation of the skill performs at most one state transition by design — the CLI, not the
  model, is the source of truth for what state an experiment is in and what may happen next.

## 0.2.0

### Added
- **`dep-egress`, the first skill in this repo.** Audits a third-party package for what it sends
  off the machine: install scripts first, then runtime calls, payload class, and transitive
  dependencies that phone home when the top-level package never says so. Eight phases, a mandatory
  coverage check that reports unreadable code as "not analyzable" rather than clean, and a verdict
  table keyed on disclosure and data class together.
- **The category was empty.** Regulatory compliance (GDPR, CCPA, HIPAA), STRIDE threat modeling and
  vulnerability review each already have several skills. Nothing evaluated a dependency you are
  about to add for data egress. Verified by searching the marketplaces before writing anything, and
  the claim is about the category, not an exhaustive sweep of every listing.
- **`.claude/skills` symlinks, generated by `sync-plugin.mjs`.** Claude Code only scans
  `.claude/skills`, not `skills/<category>`, so without a link a skill in this repo silently is not
  available while working on this repo. `--check` covers the links, so CI fails on a missing one
  instead of leaving it invisible. The script refuses to overwrite anything that is not a symlink,
  verified against a hand-written file at the link path.
- **A design-rules section in the README** stating the standard every skill here follows: one
  question per skill, an explicit not-for list, evidence or an admission that something could not
  be verified, and no values in output.

### Changed
- **README restructured** to match SKILLmama's shape, minus the logo and demo asset. Two of its
  badges were tested and dropped rather than copied: the skills.sh badge renders "resource not
  found" for this repo, and a release badge would show `skill-land v1.1.0`, which reads as a version
  for the whole repo.

### Fixed
- **`dep-egress` could have printed a credential into its own report.** The first draft said to
  quote payload construction and the opt-out switch from source, so auditing a package that ships a
  token in its payload would have reproduced that token. Replaced with an output contract: a finding
  is a location plus a field name and class, and data never appears in a report.

### Notes
- The skills.sh listing shows **Snyk W007 HIGH, Fail**, and that finding was fair when it was
  raised. The cause is fixed, but the badge has not moved: the audit is pinned to the first scanned
  revision and still quotes a sentence deleted in `c1a0451`. No re-scan trigger exists that we could
  find. Whether the rewrite satisfies W007 is **unverified**, and cannot be verified locally.
  SkillSpector is not a usable second opinion here: it scores the failing and the fixed versions
  identically at 0/100 LOW.
- Dogfooding `dep-egress` on the `skills` CLI itself found that `skills@1.5.22` gates
  `add-skill.vercel.sh/t` behind `DISABLE_TELEMETRY` and `DO_NOT_TRACK` but does not gate
  `add-skill.vercel.sh/audit`. Confirmed live with both variables set. Not yet reported upstream.
- Neither the skill nor its phases are eval'd. It was exercised against one real package, which is
  a demonstration, not a measurement.

## 0.1.0

### Added
- Repo scaffold: `marketplace.json` making this repo an installable Claude Code marketplace,
  `plugin.json` generated from disk by `sync-plugin.mjs` with a `--check` mode wired into CI, and
  category folders where `in-progress/` and `deprecated/` are excluded from the manifest.
- SKILLmama listed in the marketplace from its own repository. The local `magithar-skills` plugin is
  listed only once it contains at least one skill, since a plugin entry that installs nothing looks
  like it worked and did nothing.
- [`skill-land`](tools/skill-land/) under `tools/`, outside `skills/` so it is never scanned or
  published as a skill.
